Problem Statement

Existing Problems in AI Coding Benchmarks

Building trustworthy coding benchmarks manually is slow, expensive, and prone to subtle evaluation flaws.

Repetitive & Manual Authoring

  • Benchmarks over-index on small bug fixes instead of realistic feature development.
  • Hand-writing requirements, patches, and test suites does not scale.
  • Superficial task variations inflate task counts without testing distinct behaviors.

Unverified Quality & False Novelty

  • Proposed features may already exist in the repository base commit.
  • Weak tests pass without implementing the feature or mirror internal logic.
  • Missing regression checks hide silent breakage of existing APIs.
Solution & Innovation

Automated, Self-Auditing Task Factory

FeatureForge AI combines programmatic repository inspection, non-LLM novelty auditing, automated test/patch synthesis, and empirical verification.

Programmatic Novelty Verification

  • Parses Python ASTs and Git logs rather than trusting LLM novelty claims.
  • Demonstrated by catching and rejecting an already-existing deprecated candidate with exact AST symbol evidence.
  • Enforces distinct subsystems and RapidFuzz dissimilarity (< 75%).

Deterministic Core + Optional LLM

  • Core pipeline runs reliably without paid API dependence.
  • Optional OPENAI_API_KEY enrichment via LLMClient with automatic fallback.
  • Zero hardcoded credentials in source, tasks, or submission artifacts.

Self-Auditing Verification

Quality Auditing, Mutation Testing & Harbor

6-Dimension Quality Audit

  • Requirement-test consistency
  • Base-fail / patched-pass coverage
  • Regression safety (pass_to_pass)
  • Mutation testing
  • Reversed-order isolation
  • Repeated-run determinism

Deliberate Mutation Testing

Injects 3 targeted source mutations per task (15 total) into patched worktrees—e.g. bypassing conflicts_with, hiding aliases, ignoring NO_COLOR, or breaking ANSI width alignment.

Result: 15/15 killed (100.0%).

Harbor 0.25.0 Execution

Executes real harbor run CLI trials for both -a nop (must fail new feature, pass regressions → 0.0) and -a oracle (must pass both → 1.0).
